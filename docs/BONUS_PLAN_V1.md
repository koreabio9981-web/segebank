## 3. 후원수당 규정 초안 ([양식](BONUS_PLAN_GUIDE.md#3-수당규정서-양식-빈칸-채우기) 기준)

### 제1장 총칙

**제1조 (목적)** 이 규정은 주식회사 소개뱅크(가칭, 이하 "회사")가 다단계판매원에게 지급하는 후원수당의 산정과 지급 기준을 정한다.

**제2조 (용어)**

| 용어 | 정의 |
|---|---|
| 판매원 | 회사에 다단계판매원으로 등록한 회원. 등록비 없음 |
| PV | 상품마다 정한 실적 점수. 1 PV = 1원으로 환산 |
| 구매 확정 | 배송 완료 후 7일이 지나거나 구매자가 확정한 때. 수당은 구매 확정분만 계산 |
| 직추천 | 내가 추천인으로 등록된 판매원(1대) |
| 대 | 직추천 = 1대, 직추천의 직추천 = 2대 … |
| 활동 판매원 | 해당 정산 기간에 구매 확정 PV가 [1] 이상 있는 판매원 |
| 그룹 PV | 본인과 하위 전체 판매원의 구매 확정 PV 합계 |
| 계열 | 직추천 1명과 그 하위 전체 |
| 정산 기간 | 주간 수당: 월~일 / 월간 수당: 매월 1일~말일 |

### 제2장 직급

**제3조 (직급과 조건)** 매월 1일, 전월 실적으로 판정한다.

| 직급 | 이름 | 본인 누적 PV | 직추천 활동 판매원 | 그룹 월 PV | 계열 조건 | 롤업 개방 | 공유 지분 |
|---|---|---|---|---|---|---|---|
| 판매원 | 판매원 | — | — | — | — | — | — |
| 1등급 | 일반 | 300 | 2 | — | — | 2~6대 | — |
| 2등급 | 일반 | 300 | 2 | 1,000 | — | 2~6대 | — |
| 3등급 | 일반 | 300 | 2 | 3,000 | — | 2~11대 | — |
| 4등급 | 일반 | 300 | 2 | 10,000 | — | 2~11대 | — |
| 5등급 | 일반 | 300 | 2 | 30,000 | — | 2~11대 | — |
| 6등급 | 가맹점 | 300 | 3 | 100,000 | 3계열 각 20%↑ | 2~11대 | 30 |
| 7등급 | 대리점 | 300 | 3 | 300,000 | 3계열 각 20%↑ | 2~11대 | 35 |
| 8등급 | 지사 | 300 | 3 | 1,000,000 | 3계열 각 20%↑ | 2~11대 | 40 |
| 9등급 | 본부 | 300 | 3 | 3,000,000 | 3계열 각 20%↑ | 2~11대 | 45 |
| 10등급 | 총괄본부 | 300 | 3 | 10,000,000 | 3계열 각 20%↑ | 2~11대 | 50 |

- 직급 하락: 2개월 연속 조건을 채우지 못하면 한 단계 하락한다.
- 본인 누적 PV 300은 등록 조건이 아니라 **직급 조건**이며, 구매를 강요하지 않는다. 금액 적정성은 변호사 확인이 필요하다.

### 제3장 실적

**제4조** 실적은 구매 확정된 상품의 PV만 인정한다. 포인트 충전, 가입, 회원 모집은 실적이 아니다. 반품·취소된 PV는 해당 기간 실적에서 뺀다. 이미 지급된 수당은 제8조에 따라 회수한다.

### 제4장 수당

**제5조 (추천 수당)**

| 항목 | 내용 |
|---|---|
| 대상 | 판매원 |
| 계산 | 직추천 판매원의 구매 확정 PV × **10%** |
| 주기 | 주간 |

**제6조 (롤업 수당)**

| 항목 | 내용 |
|---|---|
| 대상 | 1등급 이상 (개방 대수는 직급표) |
| 계산 | 2대~11대 판매원의 구매 확정 PV × **대마다 1%** |
| 롤업 | 중간에 **활동 판매원이 아니거나 개방 대수가 부족한** 상위자는 건너뛰고, 그 위 조건을 채운 판매원에게 순서대로 올린다. 11대까지 올렸는데 받을 사람이 없으면 지급하지 않는다(회사 귀속) |
| 주기 | 주간 |

**제7조 (직급 공유 수당)**

| 항목 | 내용 |
|---|---|
| 대상 | 6등급 이상 |
| 계산 | 회사 전체 월 구매 확정 PV × **7%** × (내 지분 ÷ 대상자 지분 합계) |
| 주기 | 월간 |

**제7조의2 (달성 보너스)**

| 항목 | 내용 |
|---|---|
| 대상 | 3등급 이상 직급을 **처음** 달성한 판매원 |
| 금액 | 직급별 정액(예: 3등급 5만 원 ~ 10등급 500만 원, 시뮬레이션 후 확정) |
| 한도 | 월 지급 총액이 회사 전체 월 PV의 **3%**를 넘으면 같은 비율로 줄여 지급 |

### 제5장 지급

**제8조 (지급과 회수)**
- 주간 수당은 다음 주 화요일, 월간 수당은 다음 달 10일에 지급한다.
- 사업소득 원천징수(3.3%, 세율 확인 필요) 후 본인 명의 계좌로 지급한다.
- 최소 지급액은 1만 원이며, 미만이면 이월한다.
- 반품·취소로 생긴 과지급 수당은 다음 지급액에서 뺀다.

### 제6장 한도

**제9조** 1년 단위 후원수당 총액은 판매원에게 공급한 재화 가격 합계의 35%를 넘지 않는다. 연간 누적이 33%에 도달하면 그해 남은 기간의 직급 공유 수당과 달성 보너스를 같은 비율로 줄인다.

### 제7장 금지와 변경

**제10조 (금지)**
1. 등록비·가입비 징수
2. 등록·자격 유지 조건의 구매 강요
3. 회원 모집만으로 지급하는 수당
4. 수익 보장 표현
5. 가상자산으로 수당 지급

**제11조 (변경)** 이 규정을 바꿀 때는 적용일 3개월 전까지 오피스 공지와 문자로 전체 판매원에게 알린다.

**부칙** 이 규정은 다단계판매업 등록일부터 시행한다. (버전 0.1 초안)

## 4. 수당 계산 엔진 설계

### 4-1. 계산 순서 (주간 마감 예시)

```text
1. 마감: 해당 기간 구매 확정 주문 확정 (반품 접수된 것은 제외)
2. 활동 판매원 판정 (기간 PV ≥ 기준)
3. 주문마다:
   a. 추천 수당: 구매자의 추천인(1대)에게 PV × 10%
   b. 롤업 수당: 구매자 위로 올라가며 2~11번째 "받을 수 있는" 상위자에게 각 1%
4. 반품 회수분 차감 → 최소 지급액 확인 → 원천징수 → 지급 예정 생성
5. 한도 검사: 연간 누적 비율 계산, 33% 이상이면 경고·자동 감액 플래그
6. 관리자 확인 후 "확정" → 지급 파일 생성 → 판매원 오피스에 내역 공개
```

### 4-2. 롤업 계산 예시 코드

```js
// sale: { buyerId, pv } / getSponsor: 추천인 조회 / isEligible(user, depthIndex): 활동+개방 대수 확인
function rollUp(sale, getSponsor, isEligible, rule) {
  const payouts = [];
  let cur = getSponsor(getSponsor(sale.buyerId)); // 1대(직추천인) 위부터 시작
  let slot = rule.rollStart;                        // 2대 자리부터
  while (cur && slot <= rule.rollEnd) {
    if (isEligible(cur, slot)) {                    // 받을 수 있으면 이 자리 수당 지급
      payouts.push({ to: cur, type: 'ROLLUP', slot, amount: Math.floor(sale.pv * rule.rollRate) });
      slot++;
    }                                               // 못 받으면 건너뛰고(롤업) 같은 자리를 위로 올림
    cur = getSponsor(cur);
  }
  return payouts;                                   // 남은 자리는 지급 안 함(회사 귀속)
}
```

### 4-4. 데이터 구조 추가

```sql
CREATE TABLE bonus_runs (            -- 정산 실행 1회
  id BIGSERIAL PRIMARY KEY, plan_id BIGINT REFERENCES bonus_plans(id),
  period_from DATE, period_to DATE, kind VARCHAR(10),   -- WEEKLY / MONTHLY
  sales_total BIGINT, payout_total BIGINT, ratio NUMERIC(6,4),
  status VARCHAR(10) DEFAULT 'CALCULATED',              -- CALCULATED / CONFIRMED / PAID
  confirmed_by BIGINT, confirmed_at TIMESTAMPTZ
);
CREATE TABLE bonus_items (           -- 누가, 어떤 주문 때문에, 얼마
  id BIGSERIAL PRIMARY KEY, run_id BIGINT REFERENCES bonus_runs(id),
  user_id BIGINT, type VARCHAR(12), source_order_item BIGINT, slot SMALLINT,
  pv INT, amount INT, clawback_of BIGINT                -- 회수일 때 원래 항목
);
CREATE TABLE grade_history (user_id BIGINT, month DATE, grade SMALLINT, reason JSONB, PRIMARY KEY (user_id, month));
```

## 5. 테스트 기준 (개발 단계에서)

1. 엑셀 기본 가정과 같은 조직을 테스트 데이터로 만들어 **엑셀 결과(29.5%)와 1원 단위까지 일치**하는지 확인
2. 롤업: 중간 비활성자 1명, 3명, 11명인 경우 각각 기대값 검증
3. 반품: 지급 후 반품 시 다음 지급에서 정확히 차감
4. 한도: 인위적으로 33%, 35%를 넘기는 데이터로 경고·차단 확인
5. 규정 변경: 적용일이 3개월 미만이면 저장 거부
