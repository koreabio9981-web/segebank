## 4. 진행 방식

| 항목 | 방식 |
|---|---|
| 작업 관리 | GitHub Issues + Projects(보드: 할 일/진행/검토/완료), 위 ID로 이슈 생성 |
| 회의 | 스프린트 시작 계획(1시간), 매일 15분 점검, 스프린트 끝 시연(대표 참석) + 회고 |
| 코드 | 기능 브랜치 → PR → 리뷰 1명 + CI(테스트·린트·빌드) 통과 → develop → staging 자동 배포 |
| 완료 정의 | 완료 기준 통과 + 테스트 작성 + 문서 갱신 + staging 시연 |
| 보고 | 스프린트마다 1쪽 보고(완료·지연·위험·다음 목표) |
