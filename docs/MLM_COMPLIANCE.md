## 1. 결론

1. 다단계판매는 **영업을 시작하기 전에 시·도에 등록**해야 합니다. 등록 없이 하면 형사처벌 대상입니다.
2. 등록하려면 아래 네 가지가 필요합니다. 그래서 **개발보다 등록 준비가 더 오래 걸릴 수 있습니다.**
   - **자본금**
   - **공제조합 가입**(소비자 피해 보상)
   - **후원수당 규정서**
   - **재고 관리·판매 방법 서류**
3. 시스템에는 법 때문에 **반드시 들어가야 하는 기능 12가지**가 생깁니다(4장). 설계에 반영했습니다.
4. 이미 제외한 기능은 다단계 확정으로 더더욱 넣으면 안 됩니다.
   - 코인 출금
   - 수익 배분형 패키지
   - 가입비·의무 구매

## 2. 등록 준비 (대표님 할 일)

| 번호 | 항목 | 내용 | 상태 |
|---|---|---|---|
| 1 | 법인 설립 | 다단계판매업은 보통 법인으로 등록 | [ ] |
| 2 | **자본금** | 법정 최소 자본금 이상. 자료에 따라 **3억 원 또는 5억 원**으로 다르게 나옴 → **확인 필요** | [ ] |
| 3 | **공제조합 가입** | 직접판매공제조합 또는 한국특수판매공제조합. 가입 시 담보금(출자금 등)이 필요. 금액은 조합에 문의 | [ ] |
| 4 | **후원수당 산정·지급 기준서** | [수당규정서 양식](BONUS_PLAN_GUIDE.md)으로 작성 → 35% 검증 | [ ] |
| 5 | 재고 관리·판매 방법 서류 | 재고 관리, 반품, 판매원 교육 방법 | [ ] |
| 6 | 통신판매업 신고 | 온라인 쇼핑몰 운영 | [ ] |
| 7 | 등록 신청 | 주된 사무소 관할 **시·도**(서울이면 서울시)에 신청 → 등록증 | [ ] |
| 8 | 대표자 결격사유 확인 | 방문판매법 위반 전력 등이 있으면 등록 제한 | [ ] |
| 9 | 약관·계약서 | 판매원 등록 약관, 소비자 이용약관, 개인정보처리방침 | [ ] |
| 10 | 법률 검토 | 다단계 전문 변호사 | [ ] |

**순서 추천**: 1 → 4(수당규정서) → 10(법률 검토) → 2·3 → 5·9 → 7

수당규정서는 공제조합 가입 심사에도 쓰이므로 가장 먼저 시작합니다.

## 3. 꼭 지켜야 할 핵심 규칙 (확인 필요 표시 참고)

| 번호 | 규칙 | 시스템 영향 |
|---|---|---|
| R1 | 후원수당 총액은 1년 단위로 판매원에게 공급한 재화 가격 합계의 **35% 이하** | 수당 한도 관리 화면, 자동 경고 |
| R2 | 후원수당 기준 변경은 원칙적으로 **적용일 3개월 전 통지** | 규정 버전 관리, 예약 적용, 통지 기록 |
| R3 | **상품 1개 가격 상한**(고가 상품 판매 제한). 자료에 따라 160만 원 또는 200만 원(부가세 포함) → **확인 필요** | 상품 등록 시 가격 상한 검사 |
| R4 | 판매원에게 **등록·유지 조건으로 구매를 강요하거나 비용을 부담시키면 안 됨** | 가입비 없음, 의무 구매 조건 없음 |
| R5 | 판매원에게 **재고를 떠넘기면 안 됨** | 판매원 대량 구매 제한, 반품 허용 |
| R6 | 소비자와 판매원의 **청약철회(반품)** 보장. 기간은 확인 필요 | 반품 신청 기능, 수당 회수 |
| R7 | 거래마다 **공제조합에 거래 내용을 알리고 공제번호를 발급**받아 소비자에게 알림 | **공제조합 연동** |
| R8 | **판매원 등록 결격자**(예: 공무원, 미성년자, 법인 등) 등록 제한 → 범위 확인 필요 | 가입 시 확인 항목 |
| R9 | 판매원에게 **판매원 등록증(수첩)** 발급, 판매원 명부 관리 | 등록증 화면·출력 |
| R10 | **후원수당 지급 현황 정보 공개**(공정위 정보공개 등) | 연간 통계 추출 기능 |
| R11 | 상품 판매 없이 **사람 모집만으로 수당 지급 금지** | 수당은 구매 확정 매출에만 연결 |
| R12 | 판매원 **탈퇴 자유** | 오피스에서 바로 탈퇴 신청 |

## 4. 시스템에 추가되는 필수 기능

| 기능 | 화면 위치 | 설명 | 연결 규칙 |
|---|---|---|---|
| F1 **공제번호 발급 연동** | 주문 완료, 마이페이지 | 결제 완료 시 공제조합에 거래 등록 → 공제번호를 주문에 저장하고 구매자에게 문자·화면으로 안내. 취소 시 공제 해지 | R7 |
| F2 **수당 한도 관리** | 관리자 > 수당 정산 | 연간 누적 수당 ÷ 공급가 합계 실시간 표시. 30% 넘으면 경고, 35% 넘으면 확정 차단 | R1 |
| F3 **수당 규정 버전 관리** | 관리자 > 수당 규정 | 새 규정 등록 → 적용일이 3개월 이후인지 검사 → 판매원 전체 통지 → 적용일에 자동 전환. 오피스에 현재·예정 규정 공개 | R2 |
| F4 **상품 가격 상한 검사** | 판매자 개별·일괄 등록 | 설정한 상한을 넘으면 등록 거부(일괄 등록 오류 줄에 표시) | R3 |
| F5 **판매원 등록 절차** | 회원가입 | 판매원 약관 동의, 본인인증, **결격사유 확인 항목**, 등록증 발급. 가입비 0원 | R4, R8, R9 |
| F6 **판매원 등록증** | 오피스 > 내 정보 | 등록번호, 이름, 등록일, 회사 정보. 휴대폰 화면 표시·PDF | R9 |
| F7 **반품·청약철회** | 마이페이지, 관리자 | 기간 안 반품 신청 → 승인 → 환불 → **수당·PV 자동 회수** | R5, R6 |
| F8 **구매 한도** | 주문 | 판매원 1인 기간별 구매 한도(재고 떠넘기기 방지), 설정값 | R5 |
| F9 **수당 = 매출 연결만** | 수당 엔진 | 가입·모집 이벤트로는 수당이 생기지 않게 설계 | R11 |
| F10 **정보 공개 자료** | 관리자 > 통계 | 연간 후원수당 지급 현황(구간별 인원·평균 등) 추출 | R10 |
| F11 **탈퇴** | 오피스 > 내 정보 | 탈퇴 신청 → 처리. 하위 조직 처리 규칙은 규정서에 따름 | R12 |
| F12 **판매원 명부·기록 보존** | 관리자 | 판매원 명부, 거래·수당 기록 보존(보존 기간 확인 필요) | R9 |

### 4-1. 데이터 구조 추가

```sql
-- 공제번호
ALTER TABLE orders ADD COLUMN mutual_aid_no VARCHAR(40),          -- 공제번호
                   ADD COLUMN mutual_aid_status VARCHAR(12);       -- REQUESTED/ISSUED/CANCELLED/FAILED

-- 판매원 등록
ALTER TABLE members ADD COLUMN distributor_no VARCHAR(20) UNIQUE,  -- 판매원 등록번호
                    ADD COLUMN registered_at TIMESTAMPTZ,
                    ADD COLUMN disqualify_checked JSONB,            -- 결격사유 확인 응답
                    ADD COLUMN left_at TIMESTAMPTZ;                 -- 탈퇴일

-- 수당 규정 버전
CREATE TABLE bonus_plans (
  id BIGSERIAL PRIMARY KEY, tenant_id BIGINT NOT NULL DEFAULT 1,
  version VARCHAR(10) NOT NULL, rules JSONB NOT NULL,              -- 수당규정서 6장 형식
  effective_from DATE NOT NULL, notified_at TIMESTAMPTZ,
  status VARCHAR(10) NOT NULL DEFAULT 'DRAFT',                     -- DRAFT/SCHEDULED/ACTIVE/RETIRED
  CHECK (notified_at IS NULL OR effective_from >= (notified_at::date + INTERVAL '3 months'))
);

-- 수당 한도 집계 (연도별)
CREATE VIEW bonus_cap_status AS
SELECT date_trunc('year', b.period) AS year,
       SUM(b.amount) AS bonus_total,
       (SELECT SUM(oi.price*oi.qty) FROM order_items oi WHERE oi.status='CONFIRMED'
          AND date_trunc('year', oi.confirmed_at) = date_trunc('year', b.period)) AS supply_total
FROM bonuses b GROUP BY 1;
```

### 4-2. 공제번호 발급 흐름

```text
결제 완료 → [공제조합 API] 거래 등록 요청(주문번호, 금액, 구매자)
   ├ 성공 → 공제번호 저장 → 주문 완료 화면 + 문자로 공제번호 안내
   └ 실패 → 재시도(3회) → 계속 실패 시 관리자 알림, 주문은 "공제 대기"로 표시
취소·반품 → 공제조합에 해지 요청
```

연동 방식(API 제공 여부, 규격)은 **가입하는 공제조합에 확인이 필요**합니다.

## 7. 발생할 수 있는 문제와 해결

| 문제 | 해결 |
|---|---|
| 등록 전에 사이트를 열어 판매원 모집 | **등록증을 받기 전에는 오피스·추천 기능을 끈 상태로**만 운영(설정 스위치) |
| 수당 총액이 연말에 35%를 넘음 | F2 실시간 감시 + 규정서의 비례 감액 조항 |
| 규정을 급하게 바꿔야 함 | F3에서 3개월 검사. 예외는 법률 검토 후에만 |
| 공제번호 발급 장애 | 재시도·관리자 알림, 공제 대기 주문은 배송 보류 여부를 정책으로 정함 |
| 판매원 재고 사재기 | F8 구매 한도, 반품 보장 |
