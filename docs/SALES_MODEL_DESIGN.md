## 1. 결론

| 항목 | 설계 |
|---|---|
| 설정 단위 | **판매자마다 기본 판매 방식**을 정하고, 필요하면 **상품마다 바꿀 수 있음**. 바꾸는 권한은 관리자만 |
| 판매 방식 3가지 | **직매입**(소개뱅크가 사서 판매) · **위탁 판매**(판매자 물건을 소개뱅크 이름으로 판매) · **중개 판매**(판매자가 직접 판매, 소개뱅크는 오픈마켓) |
| 핵심 규칙 | **PV·수당·포인트 결제는 기본적으로 직매입·위탁 상품만 적용**. 중개 상품에 켜려면 관리자 잠금 해제 필요 |
| 이유 | 다단계 수당은 **다단계판매업자(소개뱅크)가 공급한 재화**에 붙어야 하고, 포인트가 **다른 판매자 상품**에 쓰이면 선불업 등록 대상이 될 수 있음 |

## 2. 판매 방식 비교

| 항목 | 직매입 | 위탁 판매 | 중개 판매(오픈마켓) |
|---|---|---|---|
| 법적 판매자 | 소개뱅크 | 소개뱅크 | 입점 판매자 |
| 상품 화면 "판매자" 표시 | 소개뱅크 | 소개뱅크(공급: ○○) | ○○ + **"소개뱅크는 통신판매중개자로서 거래 당사자가 아닙니다"** 고지 |
| 재고 | 소개뱅크 보유 | 판매자 보유(또는 입고) | 판매자 보유 |
| 매출 인식(확인 필요) | 판매 금액 전체 | 판매 금액 전체(또는 수수료, 계약에 따름) | 중개 수수료만 |
| 판매자에게 주는 돈 | 매입 대금(입고 시) | 판매 대금 − 위탁 수수료 | 판매 대금 − 중개 수수료(PG 정산) |
| 반품·환불 책임 | 소개뱅크 | 소개뱅크(판매자에게 청구) | 판매자(소개뱅크가 중재) |
| **PV·후원수당** | ✅ 기본 적용 | ✅ 기본 적용 | ❌ 기본 미적용(🔒 잠금) |
| **35% 기준 금액 포함** | ✅ | ✅ | ❌ |
| **공제번호 발급** | ✅ | ✅ | 확인 필요 |
| **포인트 결제** | ✅ 기본 가능 | ✅ 기본 가능 | ❌ 기본 불가(🔒 선불업 등록 후) |
| 세금계산서·현금영수증 | 소개뱅크 발행 | 소개뱅크 발행 | 판매자 발행 |

## 3. 관리자 설정

### 3-1. 판매자 단위 (관리자 › 판매자 목록 › 판매자 상세)

```text
[그린푸드] 기본 판매 방식:  ( ) 직매입  (●) 위탁 판매  ( ) 중개 판매
           수수료율: [ 12 ]%   정산 주기: [월 2회 ▼]
           ⚠ 변경하면 "새로 등록하는 상품"부터 적용됩니다.
              기존 상품을 일괄 변경하려면 [기존 상품에도 적용] 체크 (변경 내역 기록)
```

### 3-2. 상품 단위 (관리자 › 전체 상품 › 상품 상세)

| 설정 | 기본값 | 바꿀 수 있는 사람 |
|---|---|---|
| 판매 방식 | 판매자 기본값 | 관리자 |
| PV 부여 | 직매입·위탁: 판매가의 [ ]% / 중개: 0 | 관리자 |
| 포인트 결제 가능 | 직매입·위탁: 예 / 중개: 아니오 | 관리자 |
| 공제 대상 | 직매입·위탁: 예 | 관리자 |

판매자는 판매자센터에서 판매 방식을 **볼 수만 있고 바꿀 수 없습니다.** 상품 일괄 등록 양식에도 판매 방식 열은 없고, 판매자 기본값이 자동 적용됩니다.

### 3-3. 잠금 기능 (위험한 조합 방지)

| 바꾸려는 설정 | 잠금 해제 조건 | 이유 |
|---|---|---|
| **중개 상품에 PV·수당 부여** | 변호사 의견서 업로드 + 대표 2단계 인증 + 수당 규정 변경 3개월 예약 | 소개뱅크가 공급하지 않은 재화에 후원수당 → 다단계 규정·35% 기준 문제 |
| **중개 상품에 포인트 결제 허용** | **선불전자지급수단 등록번호** 입력 + 대표 2단계 인증 | 가맹점이 2곳 이상이면 선불업 등록 대상(2024-09 개정법) |
| 판매 방식 변경 후 기존 주문 | 변경 불가(주문 당시 방식으로 고정) | 정산·세금 혼선 방지 |

## 4. 주문·정산 처리

한 주문에 판매 방식이 다른 상품이 섞일 수 있으므로, **주문 상품(order_items) 단위로 판매 방식을 기록**합니다.

```text
장바구니: [직매입 김치] + [위탁 꿀스틱] + [중개 안대]
결제 화면:
  · 포인트 사용 가능 금액 = 직매입 + 위탁 상품 합계까지만
  · 중개 상품은 카드·계좌이체로 결제
  · 화면에 "안대: 판매자 ○○ (소개뱅크는 통신판매중개자)" 표시
구매 확정 후:
  · 직매입·위탁 → PV 적립, 수당 계산, 35% 기준 금액, 공제 대상
  · 중개 → 판매자 정산(판매 대금 − 중개 수수료)만
```

### 4-1. 정산 종류

| 판매 방식 | 정산 | 시점 |
|---|---|---|
| 직매입 | 매입 대금 지급(발주·입고 기준) | 입고 후 [ ]일 |
| 위탁 | 판매 대금 − 위탁 수수료 | 구매 확정 기준, 월 2회 |
| 중개 | PG 오픈마켓(서브몰) 정산 또는 판매 대금 − 중개 수수료 | 구매 확정 기준, 월 2회 |

## 5. 데이터 구조

```sql
-- 판매자 기본 판매 방식
ALTER TABLE sellers ADD COLUMN default_sales_mode VARCHAR(12) NOT NULL DEFAULT 'CONSIGN'; -- DIRECT_BUY / CONSIGN / MARKETPLACE

-- 상품별 설정
ALTER TABLE products ADD COLUMN sales_mode   VARCHAR(12) NOT NULL DEFAULT 'CONSIGN',
                     ADD COLUMN pv_eligible  BOOLEAN NOT NULL DEFAULT true,
                     ADD COLUMN mutual_aid   BOOLEAN NOT NULL DEFAULT true;
-- point_payable 은 유료회원 설계에서 추가

-- 주문 당시 값 고정
ALTER TABLE order_items ADD COLUMN sales_mode VARCHAR(12) NOT NULL,
                        ADD COLUMN pv_eligible BOOLEAN NOT NULL,
                        ADD COLUMN paid_points INT NOT NULL DEFAULT 0;

-- 잠금 해제 기록
CREATE TABLE policy_unlocks (
  id BIGSERIAL PRIMARY KEY, tenant_id BIGINT NOT NULL DEFAULT 1,
  kind VARCHAR(30) NOT NULL,            -- MARKETPLACE_PV / MARKETPLACE_POINTS / MEMBERSHIP_MODE2
  evidence_file TEXT,                   -- 변호사 의견서
  registration_no VARCHAR(40),          -- 선불업 등록번호
  approved_by BIGINT NOT NULL, approved_at TIMESTAMPTZ DEFAULT now(),
  effective_from TIMESTAMPTZ NOT NULL
);

-- 위험한 조합을 DB에서도 막기 (잠금 해제 전)
ALTER TABLE products ADD CONSTRAINT marketplace_no_pv_by_default
  CHECK (sales_mode <> 'MARKETPLACE' OR pv_eligible = false OR point_payable = false OR true);
-- ↑ 실제 차단은 애플리케이션에서 policy_unlocks 존재 여부로 검사 (DB 제약은 기본 틀만)
```

## 6. 화면 추가·변경

| 영역 | 화면 | 변경 |
|---|---|---|
| 관리자 | 판매자 상세 | 기본 판매 방식, 수수료율, 정산 주기, 변경 이력 |
| 관리자 | 전체 상품 | "판매 방식", "PV", "포인트" 열과 필터, 여러 상품 선택 후 일괄 변경 |
| 관리자 | 운영 설정 › 잠금 | 3-3의 잠금 해제 화면, 해제 이력 |
| 관리자 | 대시보드 | 판매 방식별 매출 비중, 포인트 발행잔액(선불업 기준 대비 %) |
| 판매자센터 | 판매자 정보, 상품 목록 | 판매 방식을 보기만 함, 정산 방식 안내 |
| 몰 | 상품 상세·주문 | 판매자 표시, 중개 고지, 포인트 사용 가능 표시 |
| 오피스 | 수당 내역 | PV가 붙은 상품만 실적으로 표시 |

## 7. 발생할 수 있는 문제와 해결

| 문제 | 해결 |
|---|---|
| 중개 상품에 수당을 줘서 35% 계산이 틀어짐 | 기본 잠금, 35% 기준 금액은 PV 대상 상품만 합산 |
| 중개 상품을 포인트로 사서 선불업 미등록 발행 | 기본 잠금, 결제 화면에서 포인트 사용 한도 자동 계산 |
| 판매 방식을 바꿨더니 과거 정산이 틀어짐 | 주문 상품 단위로 당시 방식 고정 |
| 고객이 판매자를 혼동 | 상품 상세·주문서·영수증에 판매자와 중개 고지 표시 |
| 위탁 매출 인식 방식 혼선 | 세무사 확인 후 설정값으로 관리 |
